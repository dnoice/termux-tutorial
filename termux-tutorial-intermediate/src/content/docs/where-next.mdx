## What you can actually do

Seven lessons, and none of them were theory — you ran all of it on real
hardware.

- **Bridge the shell to Android, and diagnose it when it doesn't.** Both halves
  installed — `pkg install termux-api` *and* the Termux:API app from the same
  source — the permission prompts granted, and the one failure signature nobody
  warns you about: a `termux-*` command that **hangs forever instead of
  erroring** means the companion app is missing or came from somewhere else.
  **Volume Down + C** gets you your prompt back.
- **Read the device.** Battery, Wi-Fi, telephony, motion sensors, GPS, the
  camera and the microphone — every one of them a command that prints JSON, and
  `jq` to pull a single value out of it. You also know what a script pointed at
  a camera really is, which is the part most tutorials skip.
- **Make Android talk back.** `termux-notification` with a stable `--id` so it
  replaces itself instead of stacking, buttons that run more of your script,
  `termux-dialog` for a question a script can act on, plus the clipboard, the
  vibrator and text-to-speech.
- **Write a script instead of retyping a command.** Shebang, `chmod +x`, a
  `~/bin` on your `PATH`, `"$1"`, `$(command substitution)`, `if` and exit
  codes, `set -eu` — and `sh -x` when the thing runs but does the wrong
  thing.
- **Run it while you're asleep.** `cron` with absolute paths and its output
  redirected somewhere real, and a straight answer for why it stopped
  overnight: Doze, App Standby, and the phantom process killer. Wake locks and
  what they cost you. `termux-job-scheduler`, where conditions beat clocks.
  `termux-boot` for surviving a reboot.
- **Serve a directory over HTTP.** `python -m http.server`, the difference
  between listening on `0.0.0.0` and `127.0.0.1`, your phone's LAN address, and
  a page loading on your laptop from a device in your pocket.
- **Open a door to the internet, and shut it again.** Why your carrier's NAT
  means port forwarding was never on the table, why the fix is an *outbound*
  tunnel, and the rules that keep that from being a mistake: never serve `~`,
  never serve `~/storage/shared`, assume the URL is public the second it prints.

Your phone now senses, decides, notifies, schedules itself and publishes. That's
not a terminal emulator any more.

:::caution[Project three is the one with teeth]
The other two stay on your device. This one hands a public HTTPS URL to
whoever finds it, and a directory that a script keeps overwriting is exactly
the kind of thing that quietly grows a file you didn't mean to publish. Serve a
directory built *for* serving, never a home or storage folder that happens to
have an `index.html` in it — and stop the tunnel when you walk away.
:::

## Commands worth meeting next

Four things that pair naturally with everything above. None of them are hard;
they're just the next handful, and each one turns a phone-shaped limitation
into a non-issue.

| Command | What it's for |
| :------ | :------------ |
| `ssh` | Type into your phone from a real keyboard. `pkg install openssh`, run `sshd`, and connect on port **8022** — Termux's sshd doesn't use 22, because ports under 1024 need root |
| `rsync` | Copy a folder between phone and laptop and sync only what changed. `pkg install rsync`; it rides over the ssh you just set up |
| `tmux` | Keep a session alive when Termux is swiped away or Android reclaims it. `pkg install tmux`, then `tmux attach` to walk back into the job that's still running |
| `sv` / `sv-enable` | Real service management from `pkg install termux-services` — start `crond` or `sshd` on launch instead of remembering to. **Restart Termux after installing it**, or the supervisor isn't running yet and nothing you enable starts |

:::caution[tmux's prefix key on a phone]
Every tmux command starts with its prefix, **Ctrl-B** — which is **Volume Down
+ B**. Not Volume Up + B: that sends **Alt+B**, and tmux will ignore it while
you wonder what's broken. Volume Down is the general one and turns *any* letter
into Ctrl + that letter; Volume Up is a short fixed list that does not include
a Ctrl.
:::

:::note[The practice terminal doesn't come with you]
The simulator on this site still only knows course one's command set — `pkg`,
`ls`, `cd`, `cat`, `tar` and friends. It has no battery, no GPS and no network,
so not one `termux-*` command from this course runs in it, and neither do the
four above. That's not a gap to work around; it's the honest boundary. From
here the real device *is* the practice environment.
:::

## And when something breaks

It will, and this course breaks in more interesting ways than the last one did —
half of these failures are Android's opinion rather than your typo.

- The [Command Cheatsheet](/reference/cheatsheet/) has every `termux-*` command,
  cron field, scheduler flag and tunnel invocation from this course on one page.
- [Troubleshooting](/reference/troubleshooting/) covers the failures this course
  actually produces: the API command that hangs instead of erroring, a
  permission denied once and never asked about again, the cron job that ran for
  a day and then quietly stopped, the script that works by hand and not from
  cron, the port that's already in use, and the tunnel that 502s because the
  server behind it died.
- The official [Termux Wiki](https://wiki.termux.com) documents every
  `termux-api` command, and [r/termux](https://www.reddit.com/r/termux/) is
  where the weirdness specific to one Android version gets worked out.
