P1Two auditors disagreed

The #8b6914 trap — and why a find-and-replace would break the build's colours

hub/src/styles/_tokens.css:193 · global.css:235 · astro.config.mjs:195 · Avatar.tsx:23

One auditor reported the hex "does not occur anywhere in the repository"; another reported all three configs quote it. Both were wrong, and the truth is a remediation hazard neither caught.

#8b6914 is live and correct as --color-warning. It is also quoted in six places as if it were --color-brand, which is #886713 — the value stepped down to clear AA. A naive replace of 8b6914 → 886713 silently changes the warning colour across all four projects.

Disposition: fix only the occurrences that describe brand, by hand, each verified in context.

P2Needs device confirmation

--shared-tmp: two lessons teach opposite mechanics

hardware/gpu.mdx:252 vs desktop/across-the-boundary.mdx:100 vs troubleshooting.md:205

gpu.mdx says proot-distro login binds $PREFIX/tmp onto the container's /tmp by default; across-the-boundary.mdx says categorically that it does not, which is the stated reason the flag exists. Troubleshooting hedges between them.

My call: across-the-boundary is correct — a default bind would make --shared-tmp a no-op, and that lesson proves the boundary with a touch-a-file test rather than asserting it. Marked for on-device confirmation before publishing, since it is a claim about third-party behaviour.
